## Sub-task 1 — Confirm

### 1.1 How we interpret it

| Phrase | Our interpretation |
|---|---|
| "confirm … with all authors" | A confirmation is a statement by that author, recorded with its date and channel. A tick we entered on their behalf is not a confirmation. |
| "obtain Dingyi's own contact/profile details directly" | Ask, and use exactly what comes back. Do not derive an affiliation from an email domain or a task-file heading. |
| "corresponding author" | Currently Chengshuai Yang. Unchanged unless the authors say otherwise — this is not ours to move. |

### 1.2 Results and analysis

**One author of three has confirmed.** Dingyi Kang's details were supplied directly on 2026-09-18: *University of Texas at Dallas*, contact *dingyi.kang@utdallas.edu*. Nothing was inferred — note that the task file's own heading carries a different institutional address, and the email domain would have implied a third answer again. Asking produced a different answer from either guess, which is the argument for asking.

**Yang and Xue have confirmed nothing yet**, and Ting Xue has no contact address on record at all — Dingyi has never been put in touch. Both are recorded as pending rather than assumed.

**The already-published PDF states the wrong affiliation.** `PUBLICATION_NOTES.md` records that on 2026-09-13 the public theory PDF was amended, at the owner's request, to list "Chengshuai Yang, Ting Xue and Dingyi Kang — **NextGen PlatformAI C Corp, USA**". The author's own answer is *University of Texas at Dallas*. So a public artifact currently carries an affiliation its own author does not hold. That amendment was made before anyone asked Dingyi, which is how this kind of error happens; it is a correction for the owner to make in the published PDF, independent of the TMLR submission.

**The affiliation the task file predicted was wrong.** It says to add Dingyi "with the company affiliation", which points at NextGen PlatformAI. The author's own answer is a university. The record follows the author, and the task file's expectation is noted here as the discrepancy it is.

## Sub-task 2 — Apply

### 2.1 How we interpret it

| Phrase | Our interpretation |
|---|---|
| "the named manuscript, author metadata and any applicable running headers" | Three places, all of which must agree. The metadata is the one that leaks even when the visible page is anonymised. |
| "Update contribution statements only with verified contributions" | Draft only Dingyi's, because only Dingyi's is evidenced by work in this repository. Leave the other two blank rather than plausible. |
| "Prepare an anonymous review build from the same source" | One source, two wrappers — not two manuscripts that must be kept in step by hand. |
| Applied, not hand-edited | A script applies the record from one structure, so the three places cannot drift apart again, and the change is reviewable as a diff. |

### 2.2 Results and analysis

The record is now a single structure in `author_record.json`, and everything author-bearing is derived from it. Four places were changed:

| Place | Before | After |
|---|---|---|
| PDF metadata `pdfauthor` | `Chengshuai Yang and Ting Xue` | all three authors |
| Running header | `Yang and Xue` | `Yang, Xue and Kang` — **but see below: this reaches the arXiv/source build, not the TMLR submission** |
| Title page author line | two authors, one affiliation | three authors, two affiliations |
| Title page contacts | correspondence only | correspondence plus Dingyi's address |

**The running-header change does not reach the submission edition either, and this record first listed it as though it did.** DK-03 drops `fancyhdr`, so the source's `\fancyhead[R]` is gone from the TMLR build, and TMLR's own style governs the header instead. Measured on page 2 of each rebuilt edition: the anonymous build carries "Under review as submission to TMLR" at y=26, while **the named build has no running header at all** — its topmost text is body copy at y=82. So the sub-task's "any applicable running headers" is satisfied vacuously for the submission: no author header is applicable there. The edit is still correct and still matters for the source and any arXiv build, but it changes nothing in the TMLR edition, and saying otherwise overstated it.

That is the same failure as the one below, caught for the author block and missed for its sibling.

**The source edit alone would not have reached the printed page.** DK-03's conversion replaces the manuscript's centred title block with TMLR's own `\author` macro, and that macro was **hardcoded inside the conversion script** — with Dingyi Kang at *NextGen PlatformAI C Corp* and an **empty email**. So the named build rendered a wrong affiliation and no contact, no matter what the source said. DK-03 left it deliberately, with a comment saying DK-02 must confirm the record; the effect until now was that the record lived in two places and the rendered one was wrong.

The fix is that `update_author_record.py --emit-tmlr-author` generates the TMLR block from the same structure, so the conversion consumes the record instead of restating it. Rebuilt with the generated block, the named title page reads:

```
Chengshuai Yang        spiritai@platformai.org      NextGen PlatformAI C Corp, USA
Ting Xue                                            NextGen PlatformAI C Corp, USA
Dingyi Kang            dingyi.kang@utdallas.edu     University of Texas at Dallas, USA
```

Ting Xue's line carries no address because none is on record. That is a visible gap on the title page, and it should stay visible until Xue supplies one.

**Contribution statements.** Only Dingyi's is drafted, in the private record, and every clause of it points at a PR or task record in this repository. Yang's and Xue's are left empty: writing a plausible statement for another author is exactly the "anticipated contributions as historical fact" the task file forbids.

**The anonymous build was scanned rather than assumed clean.** Full text plus metadata of all 63 pages, searched for `Chengshuai`, `Ting Xue`, `Dingyi`, `Kang`, `utdallas`, `platformai`, `NextGen` and `Texas at Dallas`: **every term absent**. Both builds are 63 pages with 0 undefined references.

**Analysis.** The interesting failure here was not in the source but between two tasks. DK-02 owns the record and DK-03 owns the format, and the author block sits in both — so a correct edit in DK-02's territory was silently overwritten by a placeholder in DK-03's. Neither task's own tests would have caught it; only rendering the page and reading it did. The record is now generated from one structure precisely so the next person to change an affiliation cannot half-change it.
