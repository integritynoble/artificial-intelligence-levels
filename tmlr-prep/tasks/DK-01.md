## Sub-task 2 — Build and compare

### 2.1 How we interpret it

| Phrase | Our interpretation |
|---|---|
| "build the recovered source" | Compile in a **fresh, empty directory** with only the delivered files, using documented commands, and keep the log: exit codes, warning counts, page count, output hash. A build that only works in the author's directory is not a recovered build. |
| "compare against v2.6" | A structural, item-by-item comparison, not an impression: every section, table, figure, equation and reference in v2.6 must be located in the build, or its absence explained. |
| "all … accounted for" | Each item is either matched (with its new number, if it moved), newly added, or explicitly recorded as missing. Renumbering counts as accounted-for only if the mapping is written down. |
| "separate original observations, reconstructed rows and missing evidence" | Each reported measurement is assigned one class, taken from the archive's own manifests rather than inferred. |
| Not part of this sub-task | Recomputing the numbers (DK-05), or judging the claims (DK-04). |

### 2.2 What we did

| Step | Action |
|---|---|
| 1 | Copied the delivered source into an empty directory and ran `pdflatex -interaction=nonstopmode main.tex` repeatedly, logging each pass. |
| 2 | Scanned the final log for undefined references, missing citations, overfull/underfull boxes and undefined control sequences. |
| 3 | Tested a **byte-reproducible** build (`SOURCE_DATE_EPOCH=1600000000 FORCE_SOURCE_DATE=1`) and repeated it to confirm identical bytes. |
| 4 | Compared the build with v2.6 mechanically: contents entries, table captions matched one by one, figure captions, numbered equations compared by content, and the reference list. |
| 5 | Regenerated both figures with `make_figures.py` and compared them with the shipped PDFs by rendering both at 110 dpi and reading them side by side. |
| 6 | Traced where each published addendum page (66–69) now lives in the body — on re-review, **all 13 numbered addendum sections** individually, not only the ones the handover named. |
| 7 | Classified every measured result as original, reconstructed, in-line only, or missing, using the dataset manifests and `LIMITATIONS.md`. |
| 8 | On re-review: compared the **abstract** word by word, located equations (12), (15) and (17) by hand (the automated extraction skips multi-line fractions), confirmed appendices A–D, checked the package list for anything non-standard, counted `\bibitem` entries in `main.bbl`, and re-verified `hashes.txt`. |
| 9 | On a third pass: rendered **both documents' figure regions** and compared them directly (previously only the shipped-vs-regenerated figures had been compared); ran `cmp` between the figure-code CSVs and the archived CSVs inside the dataset (previously only their manifest hashes were compared); and checked the inventory against a file listing of `paper-sources/`. |

**Analysis.**
1. **The source is confirmed as the paper's source, and nothing from v2.6 is lost.** Every one of the 45 tables, 2 figures, 19 equations and 30 references is accounted for, and the only additions are the ones the handover described. The "matching source not found" gap from the publication notes is closed.
2. **The build is cleaner than expected and reproducible**, which matters for DK-09: a fixed-timestamp build gives a stable hash to approve, instead of a hash that changes every compile.
3. **Two passes are not enough.** A reviewer or arXiv build following the documented instructions would get a wrong table of contents. Small, but it is a defect in the delivered instructions (proposal A1).
4. **The submission cannot be described as "v2.6".** It is v2.6 plus §11.7, §11.9 and a renamed §15.2, minus the v2.5 dataset-binding block, with a different naming note. Those differences need the owner's explicit acceptance, and the TMLR content map (DK-03) must list them (A5).
5. **The +1 table shift is a trap for our own work.** The DK-04 change log and the DK-06 record cite v2.6 numbers. They must be re-anchored before anything is applied (A7). **The same trap applies to one section number**, and the first version of this record missed it: inserting §11.7 pushed v2.6's §11.7 down to §11.8. Comparing all 108 v2.6 headings against the build's 109 shows §11.7 is the *only* section number whose meaning differs — which makes the risk small but exact, and DK-04's change log does cite it.
6. **The figure defect is now fixable.** The wrong panel labels ("Eq. (9)", "Eq. (10)") live in `make_figures.py`, so DK-03 can correct them and regenerate rather than leaving a known error in a figure.
7. **Evidence separation is complete** and is the boundary for DK-05: 24 original episodes, 48 reconstructed rows, two curves with tables only, and a named list of never-archived material.
8. **One rule is genuinely lost, and it is the one DK-06 already flagged.** The v2.6 addendum states the continuous per-domain rule for Cognitive Intelligence (`q*_{C,k,d} = min_{j≤k} q_{C,j,d}`, with domain aggregation after within-domain retention). The source keeps the qualitative statement but not the formula, and Eq. (14) covers only `{I, O, SA}`. Since the addenda are not re-appended, dropping it also removes the only place where §14.2's claim that every achievement variable "already enforces lower-level retention" holds for C. One sentence restores it (proposal A8); decide it together with DK-06 proposal P3.
9. **The abstract is not identical to v2.6**, which matters more than a body edit: it is the first thing a reviewer reads, so the added sentence belongs in the A5 acceptance rather than being noticed later.
