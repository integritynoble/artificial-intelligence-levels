## Sub-task 1 — Trace and recalculate

### 1.1 How we interpret it

| Phrase | Our interpretation |
|---|---|
| "every reported numerical result" | Every number the paper presents as measured, not only the headline ones: per-rung values, counts, medians, test statistics, intervals, and the worked example. Each is listed and given a verdict, so "not checked" never hides among "checked". |
| "trace to its artifact" | Name the file the number comes from, the executor and harness configuration, the sample size and seed set, and the metric definition as the paper states it. A number whose artifact cannot be named is a finding, not a gap to pass over. |
| "recalculate" | Recompute from the **raw rows** with a fresh implementation of the paper's printed definitions. Running the archive's own `analyze.py` and finding agreement would prove only that one program is self-consistent. |
| "explicitly label calculations based only on published tables" | Where no artifact exists, say so and mark the check as arithmetic-only: it can catch a summary inconsistent with its table, never a wrong measurement. |
| Agreement | The recomputed value rounds to the printed value at the precision the paper prints. |

### 1.2 What we did

| Step | Action |
|---|---|
| 1 | Listed every reported number with its location, transcribed by hand into `recompute.py` so the comparison is explicit and auditable. |
| 2 | Reimplemented the paper's definitions from its own text: A_DI as the weighted band mean with the predeclared weights 1, 2, 4, 8; the net primitive at ρ=1 clamped at zero; Harness Gain, AIL-AUC and AIL-Ceiling; the regime-switch pass rule from the study manifest; exact two-sided binomial tests for the sign and McNemar comparisons; the continuity-corrected Wald interval. |
| 3 | Ran the recomputation against the archive's raw rows and compared every value with the paper. |
| 4 | Cross-checked against the archive's own `analyze.py` and `validate.py` afterwards, as a second opinion rather than the primary method. |
| 5 | For the two curves with no released rows, checked internal arithmetic consistency from the paper's own tables, labelled as such. |
| 6 | Recovered the per-band surface for the released curve, which the paper's reproducibility sentence implies exists. |
| 8 | On a third pass: opened `resource_summary.csv`, which no earlier pass had; checked the run-log fields the paper's own standard requires (false rejections, the null acceptance field at HG0, the termination reason); and confirmed which column Table 38's "Attempts" reports, since harness iterations and model calls differ at HG2. |
| 7 | On a second pass: checked **every printed cell** of the two per-seed tables (132 values) rather than only the aggregates they summarize, and checked the protocol and resource claims stated in prose — the timeout, held-out points, noise fraction, wall-time ranges, exit codes, task classes, seeds per class, intervention budget and the excluded seed. |

### 1.3 Results and analysis

Full table in **`tmlr-prep/dk05/claim_to_evidence.md`**; raw output in `recompute_log.txt`.

| | Count |
|---|---|
| Reported values recomputed from released evidence | **53** |
| Reproducing the printed value | **52** |
| Individual cells of Tables 34 and 35 checked against the CSVs | **132**, all agreeing |
| Protocol, run-log and resource claims checked | **17**, all agreeing |
| Genuine discrepancies | **1** |
| Result groups with no released artifact | 12 |

**The regime-switch study (§17.10) reproduces exactly** — every pass/fail verdict, 5/12 against 1/12, RMSE lower on 11/12, sign test p = 0.00635, McNemar p = 0.125, the −1.7 to +68.3 interval, both medians, and both retraction-related seeds.

**The harness-scaling curve (§18.4) reproduces for the one released executor** — every A_DI, HLIS_DI, net figure, false-completion count, held-back count and attempt count in Table 38, plus the gain, ceiling, AUC and headroom.

**One genuine discrepancy.** §18.4.7 says "two executors rose +3.4 there"; Tables 39 and 40 print the same quantity as 3.3. The sentence subtracts the rounded rungs (96.7 − 93.3); the unrounded values give 3.333, which prints as 3.3. The tables are right, the sentence is wrong.

**Analysis.**
1. **The measured claims hold up.** Two independent implementations and the printed values agree on 52 of 53 numbers, and the one exception is a rounding slip in prose, not a data problem. For a paper whose own §17 is about audit discipline, that is a good result and worth saying plainly to the owner.
2. **The reproducibility sentence overstates what is released**, in two ways. It says per-band success rates are "reported in-line so the reported A_DI can be recomputed by hand from the tables" — no table carries them. And it says "the released episode rows reproduce every entry of Table 38" — Table 38 has three executors and the rows cover one.
3. **The curve is narrower than the numbers suggest.** Of six task classes, only `t1.clean_dataset` ever fails: six failing episodes in 48. The entire movement from 93.3 to 96.7 is one episode of one class. This is consistent with the paper's own saturation warning, and it is worth keeping visible in any summary.
4. **Checking the tables cell by cell, not just their summaries, was worth doing.** The first pass verified the aggregates — medians, counts, test statistics — which would still have agreed if an individual row had been mistyped. All 132 cells agree, including every "vs. bar" ratio and every three-way outcome label, so the per-seed tables are sound as printed.
5. **The archive resolves two claims that were previously unverifiable**: §18.4.3's "both fail only one class" and "A fails seed 0" at HG2 and HG3. Both hold exactly.

## Sub-task 2 — Evidence classes and anomalies

### 2.1 How we interpret it

| Phrase | Our interpretation |
|---|---|
| "preserve the distinction between reconstructed rows and original logs" | Every recomputed value carries its evidence class. A number that reproduces from reconstructed rows is *consistent with the reconstruction*, which is weaker than reproducing from an original log, and the difference must stay visible. |
| "inspect its inputs, intermediate values and output against a passing case" | For an anomalous seed behind a retained claim, look at the actual row and compare it with a passing row before saying anything about it. |
| "use archived outputs/offline computation first" | Everything here is offline arithmetic over released files. **No model was run and no cost was incurred.** |
| "seek approval before a paid rerun" | Not reached: nothing needed a rerun. |

### 2.2 What we did

| Step | Action |
|---|---|
| 1 | Took the evidence class for each result from the archive's own manifests and `LIMITATIONS.md` rather than inferring it. |
| 2 | Tagged every row of the claim-to-evidence table: archived, reconstructed, or published-table only. |
| 3 | Inspected the two anomalous seeds behind the retraction the paper reports, comparing them against passing rows. |
| 4 | Checked the failing episodes of the released curve individually: which class, which seed, which rung, and whether they were false completions or held back. |

### 2.3 Results and analysis

| Result | Evidence class | Consequence |
|---|---|---|
| Regime-switch study (§17.10) | **Archived.** Both CSVs' hashes match the study manifest, and they are byte-identical to the copies shipped with the figure code | Reproduction is genuine |
| Harness curve, Family A stronger (§18.4) | **Reconstructed** from the runner's aggregate log; the HG0 acceptance verdict and the termination reason were never archived per row | Reproduction confirms the reconstruction is internally consistent with Table 38, not that the original run produced those rows |
| Family B, Family A weaker, the paired rerun | **Published tables only** | Arithmetic consistency only |
| §17 item families, §16.1 counts, §15.3 anecdote, the M1 claim | **No artifact** | Not checkable at all |

**The anomalous seeds.** The paper reports a retraction: seed 11 was published as a capability failure at RMSE 0.258 and passes at 0.021 once the executor had time to finish. In the archive, seed 11 carries `extrapolation_rmse = 0.021` against a bar of 0.0435 — a pass, with the mechanism stated and exit code 0, matching a passing row such as seed 40 in every structural respect. Seed 27, the other corrected case, shows 0.060 against a bar of 0.934. Both corrections are in the archive as the paper describes them, so the retraction is honest and checkable.

**The failing episodes.** All six sit in `t1.clean_dataset`: both seeds at HG0 (recorded as false completions), both at HG1 (held back), and seed 0 alone at HG2 and HG3. Nothing anomalous — the pattern is exactly what §18.4 describes, and it is the whole source of the curve's movement.

**Analysis.** The evidence classes matter more than the pass rate here. Every §18.4 number reproduces, but from rows the archive itself labels reconstructed, so the honest statement is "the released rows are internally consistent with the published table", not "the experiment was reproduced". The paper already says this; our table keeps it attached to each number.
