## Sub-task 1 — Rebuild and inspect

### 1.1 Results and analysis

All five frozen inputs hash-matched DK-01's inventory before anything was built. Both variants then built at 63 pages, 0 undefined references, **0 overfull boxes** — which was worth confirming rather than assuming, since 46 tables in a narrower text block is exactly where overfull boxes appear.

**Rebuilding from the documented inputs produced a defective candidate, and that is the finding.** Figure 2's panel labels read "Success-only primitive, **Eq. (9)**" and "Delivered-outcome primitive, **Eq. (10)**", while the body text on the same page cites **Equation (16)** for that same primitive. A reader following the figure to the equation lands on the U-level gates instead.

The cause is a gap between tasks, not a mistake in either. DK-03 diagnosed these labels and wrote `regenerate_figures.py` to strip the numbers — and DK-03's own committed PDF is correct. But the conversion copies `fig_hsc.pdf` straight from the source tree, so the repair only lands if you separately run the regeneration first. It is a second, manual step, and nothing fails if you skip it. Rebuilding exactly as documented skips it.

**The build also has an undeclared dependency.** That regeneration step needs matplotlib, and **no interpreter on the build machine had it** — the documented command could not be run as written. A virtual environment with matplotlib 3.11.2 was needed. That is not the version that produced the released figures, so the regenerated figures are not byte-identical to them, and this build is not byte-reproducible even though the LaTeX half is.

**Anonymous and named builds carry the same science.** Normalising away page numbers, running headers and the TMLR banner leaves 2,518 lines against 2,522, differing on **8 lines, every one of them the author block**. Nothing scientific differs.

**Every page was inspected by rendering and reading it**, 63 of 63, not sampled:

| Check | Result |
|---|---|
| Text near the page edge, all 63 pages | 0 |
| Overfull boxes | 0 |
| Fonts embedded | 35 of 35 |
| Missing-glyph replacement characters | 0 |
| The indicator glyph that printed wrong in v2.6 | Correct — `\mathds{1}` renders |
| Figures legible | Both |
| Tables, equations, appendices A–D | All render |

One cosmetic observation: the figures embed **Type 3** fonts, inherited from matplotlib. Not fatal and TMLR does not forbid them, but they rasterise poorly when zoomed and some venues discourage them; setting `pdf.fonttype = 42` in the figure code would emit Type 42 instead.

**The published figure code does not reproduce the published figures.** The released `fig_hsc.pdf` and `fig_regime.pdf` record their own provenance in their metadata — *Matplotlib v3.10.8* — so the version question is answerable rather than lost. Installing exactly 3.10.8 and running the published `make_figures.py` still does not reproduce them:

| | Released | Rebuilt from the published code |
|---|---|---|
| `fig_hsc.pdf` | 475.2 × 187.2 pt (6.6 × 2.6 in) | 518.4 × 208.8 pt (7.2 × 2.9 in) |
| `fig_regime.pdf` | 475.2 × 208.8 pt (6.6 × 2.9 in) | 518.4 × 223.2 pt (7.2 × 3.1 in) |

The plotted content is equivalent — the extracted text differs only in reading order — but the canvas is about 9% wider in both cases, because the code's `figsize` is `(7.2, 2.9)` and `(7.2, 3.1)` while the released figures were drawn at 6.6 in wide. `bbox_inches="tight"` does not account for it either; that yields 509 × 200 pt, closer but still not the released size. So the figure code in `paper-sources/figures/` is **not the code that produced the figures in the paper**, and anyone rebuilding them gets noticeably larger panels.

This has a direct consequence for the candidate: because the equation-label repair requires regenerating the figures, **the candidate's figures are ~9% larger than the released ones**, which is a real if modest layout change. Correcting `figsize` to `(6.6, 2.6)` and `(6.6, 2.9)` would remove the difference.

**The interior-whitespace item DK-03 deferred here is now closed.** DK-03 reported three interior pages carrying roughly 100 pt of white space and left the measurement for this task. Measuring gaps between body lines only, excluding the header, the footer and short final pages:

| Page | Largest interior gap |
|---|---|
| 48 | 86.2 pt, and a second of 80.8 pt |
| 42 | 70.4 pt |
| 59 | 61.2 pt |

Four gaps over 55 pt across three pages, the largest 86 pt — down from the ~100 pt DK-03 saw, so the float tuning did help. Every one sits beside a large table, which is ordinary float spacing rather than a layout failure. Recorded as measured and acceptable rather than left open.

**Three further checks were run, and all three are clean.** They are recorded because a check that finds nothing is only worth something if you can see it was run.

| Check | Method | Result |
|---|---|---|
| Hand-typed cross-references | Every `§N`, `Table N`, `Figure N` and `Equation (N)` in the prose matched against the targets that exist | 38 sections, 46 tables, 2 figures, 4 equations cited — **0 unresolved** |
| Figures against the paper's own tables | `hsc_curves.csv`, which Figure 2 plots, compared cell by cell with Table 39 | **12 of 12 cells agree** |
| Figures against the released archive | `regime_switch_frontier.csv` and `..._haiku.csv`, which Figure 1 plots, hashed against the archive's `frontier.csv` and `haiku.csv` | **byte-identical** |
| Bibliography | `\cite` keys against `references.bib` entries | 30 entries, 30 cited, **no orphan either way**, 0 BibTeX warnings |

The cross-reference check matters more than it sounds. LaTeX reported 0 undefined references throughout, but that only covers `\ref`; a number typed straight into the prose is invisible to it, and stays wrong when the manuscript renumbers. That is precisely how the figure's equation labels went stale. It is now the verifier's sixth check, so the class cannot recur unnoticed.

**Every check is now a positive control, not just check 4.** The first version of this record could only say the figure-label check had been proven to fire. A check that has never failed is indistinguishable from a check that cannot fail, so each of the six was tested against a deliberately broken build:

| # | Check | Fault injected | Fired? |
|---|---|---|---|
| 1 | Equivalence | A sentence rendered only in the named edition | **Yes** — "1 not explained by the author block" |
| 2 | Geometry | An unbreakable 116-character token | **Yes** — "page 2: text within 18.0pt of the right edge" |
| 3 | Fonts | A build assembled without the full font set | **Yes** — "3 not embedded" |
| 4 | Figure labels | The pre-repair figure with "Eq. (9)"/"Eq. (10)" | **Yes** — 2 stale labels |
| 5 | Anonymity | An author name and affiliation written into the body | **Yes** — 3 identifying terms |
| 6 | Cross-references | A citation of "Table 99", which does not exist | **Yes** — "Table: 47 cited, 1 unresolved" |

Each faulty build exited 1; the real candidate exits 0. Check 5 matters most of the six, and it is now the one least taken on trust.

**The checks are a script with a control.** `verify_candidate.py` runs all five and exits non-zero on any finding. It was confirmed to fail on the stale candidate (2 findings, exit 1) and pass on the corrected one (0 findings, exit 0), so it is known to detect the defect it was written for rather than merely passing.

## Sub-task 2 — Snapshot integrity

`python3 -B tools/verify_public_snapshot.py` **passes**: 159 payload hashes and sizes, 155 dataset files matching all 155 ZIP members, 89 JSON and 43 JSONL files, 82 method and 82 matrix records.

It failed on the first run, and the cause was ours: running the published scorers during DK-06 left four `__pycache__/*.pyc` files in the dataset directory, which the manifest correctly rejects. They are git-ignored and never reached any PR. This is exactly why the task file specifies `python3 **-B**` — the flag exists to stop the verification from contaminating what it verifies.

Reported as integrity verification only. It says the published bytes match their manifest; it says nothing about whether the science is right.
